# 正式剧情节点

本目录保存已经确认、且后续章节必须继承的正式剧情节点。节点正文是剧情变化真源；动态消费状态只记录在 `_status/`，节点文件不随状态移动。

## 入口

- [_template.md](_template.md)：正式剧情节点模板。
- [主线](主线/_index.md)：核心矛盾、案件链、制度解释权与终局秩序。
- [副线](副线/_index.md)：人物现实后果、职业压力、机构场域与局部事件。
- [亲密线](亲密线/_index.md)：跨阶段、可反复调用的亲密关系节点。
- [动态状态](_status/)：pending、active、completed、retired 四态入口。

## 归档规则

- 一级目录固定为 `主线/`、`副线/`、`亲密线/` 和 `_status/`。
- `主线/` 与 `副线/` 的二级目录固定为 `人物/`、`组织/`。
- `人物/` 同时容纳单人主体与多人主体；多人共同承接时，直接以人物组名称建立归档主体目录。
- 事件不单独建立目录；每个事件必须绑定到实际承担持续变化的人物或组织。
- 无法确定人物或组织承接者的事件，先留在分析或待确认层，不进入正式剧情节点。
- `亲密线/` 继续直接按第一剧情主体归档，不增加重复的 `人物/` 中间层。
- 每个节点只按一个“归档主体”保存一次。
- 节点正文必须登记“主体类型”“归档类型”“归档主体”“中心人物”。
- `主体类型` 说明节点侧重，不决定物理目录；`归档类型` 只使用人物、组织。多人主体由归档主体和中心人物表达；节点侧重群体后果时可使用 `主体类型：群像线`。
- 目录表示归档类型和唯一归档主体；文件名中的人物前缀表示共同中心人物。
- 多名人物之间使用乘号 `×`，人物组与剧情线名称之间使用 `-`。
- 多人节点可以使用唯一的人物组目录，不按参与者重复保存正式节点。
- 章节 POV 由章纲、预写或施工层决定，不由“中心人物”字段代替。

## 状态入口

- [_status/pending.md](_status/pending.md)：已经升格、但尚未形成定稿事实。
- [_status/active.md](_status/active.md)：已经开始兑现、但尚未满足全部完成判据。
- [_status/completed.md](_status/completed.md)：已经完成闭环。
- [_status/retired.md](_status/retired.md)：已取消或已由新节点替代。

## 派生边界

`story-writer plotline preview` 只从本目录、`_status/` 与 `story/arcs/` 生成临时可视化；人物和世界观关联只取节点已写明的正式引用路径，不读取被引用文件正文。Preview 产物位于系统临时目录，不是故事真源，也不得反向定义故事事实。

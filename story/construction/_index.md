# 施工真源索引

> `story/construction/` 保存作者已经确认、写作时必须继承的执行规格。它是真源，但不是长期正典；若与 `BIBLE.md`、正式目录或已定稿章节冲突，服从更高层真源。

## 收录边界

- 收录已经确认的场次顺序、衣装、对白议程、章节分配与其他具体执行规格。
- 不收录候选、待确认项、方案比较、确认过程、废案或历史分析；这些内容保留在 `.analysis/`。
- 每个施工单元只服务已经登记的正式剧情节点，必须能够追溯到至少一个 `story/plotlines/` 下的 `PL-*` 节点；无法建立正式接口的内容不得登记为生效施工单元。
- 稳定人物事实、关系变化、世界规则与跨章状态必须同步进入对应正式目录，不能只依赖施工文件。
- 正文或定稿完全取代某份施工规格后，将对应施工单元转为 `consumed`，默认检索不再返回。

## 生命周期

- [active](./_status/active.md)：已确认并生效；普通检索默认读取。
- [bound](./_status/bound.md)：已挂接具体章节或场景；仅匹配目标时读取。
- [consumed](./_status/consumed.md)：已被定稿或更高层真源完整吸收；默认排除。
- [superseded](./_status/superseded.md)：已被另一施工单元替代；默认排除。
- [retired](./_status/retired.md)：已取消；默认排除。

每个施工文件使用稳定 `CON-xxxx` ID，并且必须恰好登记在一份状态文件中。不记录“已读／未读”；只记录规格是否仍生效、挂接、兑现、替代或取消。标准流转为 `active → bound → consumed`；只兑现一部分时继续保持 `bound`，或先拆成更小施工单元。

## 状态登记协议

五份状态表使用相同字段，职责不得混用：

- **施工 ID**：稳定且唯一的 `CON-xxxx`。
- **施工单元**：必须是指向该 `CON-xxxx` 唯一源文件的 Markdown 链接；不得填写剧情线分类、剧情节点链接或施工包名称。
- **剧情线归属**：填写唯一主要归属，使用正式剧情线索引中的层级，例如 `主线 / 人物 / 晏林`、`副线 / 组织 / 云顶KTV` 或 `亲密线 / 晏林`。一个施工单元可以服务多类节点，但只能有一个主要归属。
- **剧情节点接口**：至少填写一个当前有效的正式 `PL-*` ID；多个接口并列登记。这里记录施工规格服务哪些正式节点，不代替节点正文中的反向“施工单元接口”。
- **生效范围／挂接目标**：`active` 必须填写当前适用范围；`bound` 必须填写唯一章节或场景目标。此列不得拿来存放剧情节点接口。
- **兑现／替代位置**：`consumed` 必须填写兑现位置，`superseded` 必须填写替代它的新 `CON-xxxx`；其他状态按需填写。
- **备注**：只解释迁移来源、状态原因或必要边界，不保存候选方案和确认过程。

状态迁移时移动整行，不复制登记。任何一行缺少源文件链接、主要剧情线归属或正式剧情节点接口，都视为未完成登记；对应内容不得被普通写作任务继承。

施工索引以 `_status/` 中登记的路径为内容清单。`active`、`bound` 建立完整正文索引；`consumed`、`superseded`、`retired` 只保留状态、兑现位置与源路径，历史正文需要复查时再按源路径读取。目录遍历只用于发现漏登记文件，不作为内容入口。

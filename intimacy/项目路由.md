# 亲密专项项目路由

> 本页是 `story-stars` 的项目自有路由，不属于 intimacy package managed roots，不保存人物偏好、场次结论或其他故事事实。

## 进入条件

1. 先运行 `sw specialty resolve intimacy --root <project>`。
2. 只有在 `activation=enabled`、`ready=true` 且无 blocking diagnostic 时，才读取本项目的 `intimacy/` 安装副本。
3. 亲密任务仍先服从项目 `POLICY.md`、`BIBLE.md`、`STYLE.md` 与正式大纲；Specialty 不得覆盖项目真源。

## 项目边界

- 所有敏感章节的成人亲密内容必须服从 [18+HD 纯肉题材口径](../story/genres/18+HD纯肉.md)；人物事实、当场选择与前后文承接回读对应正式真源。
- 正式大纲或作者已指定 A／B／dark 时，直接继承该结论，不在专项层重新判型。
- `protocols/`、根 `_index.md`、`references/_index.md` 与 `references/library/` 由 package 管理；项目自有的角色档案、机制、上下文与参考素材不反向写回 package source。

## 读取顺序

1. 读项目 `BIBLE.md`；写作、修订或审读正文时再读 `STYLE.md`。
2. 读 `story/genres/_index.md` 与本任务命中的题材页。
3. 读正式大纲、人物卡、上下文及已定稿章节组成的任务闭包。
4. 从 package-managed [专项协议](protocols/_index.md) 进入本任务命中的方法页。
5. 命中道具、衣装、场域、影像、多人或连续性问题时，再从 [项目专项机制](mechanisms/_index.md) 进入。
6. 需要具体写法素材时，最后从 [项目参考索引](references/项目索引.md) 按需查阅；参考不生成人物事实或授权。
7. 正文回写仍以 `chapters/` 中对应草稿为承载文件；只有形成长期关系或剧情变化时，才按已有定稿流程同步长期状态。

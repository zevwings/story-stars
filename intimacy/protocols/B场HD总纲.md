# B 场 HD 总纲

> 本页只定义正向 B 场 HD 的公共施工协议。具体身体词条、动作、场域、题材机制与项目尺度, 读取项目真源和 `$SPECIALTY_ROOT/references/`。

## 进入条件

- 参与者满足项目年龄与内容边界。
- 场景已按项目 `BIBLE.md` 与题材页定性为正向。
- 项目要求的意愿、知情、停止与承载条件成立。
- 已存在 `design.a.md` 与 `design.b.md`。
- 人物关系阶段、当次动机和场后落点明确。

不满足时不进入正文。是否转黑暗流程必须回到项目场型判据；公共规则不因某个机制、处境或单项风险自行改判。

## 核心目标

B 场不是单纯增加尺度。每场至少完成:

- 一项关系变化。
- 一项人物或现实状态变化。
- 一项情绪兑现。

项目机制若参与本场, 还必须写清触发、作用、边界与后果, 但公共规则不定义机制内容。

## 施工顺序

1. 建立当次愿意与可停空间。
2. 选择一个主要感官或权力抓手。
3. 让动作、心理与回应同步升级。
4. 在升级点保留确认、降速或停顿。
5. 峰值后写回稳、照料和现实回流。
6. 将新增事实同步到项目要求的位置。

## 项目资料路由

按顺序读取:

1. `BIBLE.md`、`STYLE.md`
2. `story/genres/_index.md`
3. `$SPECIALTY_ROOT/mechanisms/_index.md`
4. `$SPECIALTY_ROOT/references/_index.md`
5. 角色卡、亲密档案、当次设计卡与相关世界观真源

项目没有登记的机制、器物、偏好、场域和表达方式不得临场补出。

## 质量底线

- 动作必须改变人物体验, 不能成为器械清单。
- 强度通过节奏、反应和关系意义成立, 不靠词汇堆叠。
- 人物失控仍要保留人物自己的表达方式。
- 场后不能直接跳走, 必须承接身体、情绪、关系或现实后果。
- 项目参考只提供素材, 不反向生成事实或许可。

# 关系动员与办事链

## 链条

按下列顺序设计；无实际作用的环节可以省略，但不得用一句“托关系办了”跨过关键因果。

1. **需求成形**: 谁在什么时限内需要什么；正常路径为何不足、太慢、太贵或不可达。
2. **关系盘点**: 发起者知道哪些入口；哪些是自己的人，哪些只是“认识的人”。
3. **选中入口**: 选这个中间人是因为亲近、欠情、位置合适、能保密，还是公开拒绝代价高。
4. **试水**: 先问情况、请教规则、提一个较小请求，还是直接把完整请求压过去。
5. **中间人翻译**: 中间人通常会删减、包装、降格或附加自己的担保，不是无损转发器。
6. **资源方计算**: 对方判断权限、风险、收益、关系距离、公开程度和未来回报。
7. **回应形态**: 接下、部分接下、转正规程序、只给信息、拖延、转交、软拒绝或反向索取。
8. **执行摩擦**: 即使答应，也要经过具体人员、时间窗口、文件、排期和责任归属。
9. **结果回传**: 好消息和坏消息由谁说、怎样说；中间人是否截留责任或邀功。
10. **关系结算**: 谁认为欠了谁，欠到什么程度；哪些旁观者因此重新判断各方。

## 每一跳的字段

| 字段 | 问题 |
| --- | --- |
| 节点人物 | 此人为什么在链上，换人会失去什么 |
| 可用资源 | 能决定、影响、介绍、延后、解释还是见证 |
| 开口依据 | 感情、互惠、职责、共同利益、面子压力或威胁 |
| 承担成本 | 此人具体失去什么，不写抽象“风险很大” |
| 可见动作 | 电话、转发、约见、陪同、沉默、拖延、补材料等 |
| 退出方式 | 在哪一步能拒绝、降格、转程序或切断责任 |
| 新状态 | 事情、关系、知情、声誉和人情账分别怎样变化 |

## 失败也必须有因果

失败不等于链条无效。一次没有办成的请托仍可能换来规则信息、暴露资源边界、确认谁不愿担责、消耗中间人信用、制造下一次可用入口，或让人物决定改走公开程序。

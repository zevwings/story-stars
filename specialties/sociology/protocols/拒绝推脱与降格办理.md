# 拒绝推脱与降格办理

## 拒绝不是单一动作

根据人物目标和关系成本选择形态：

| 形态 | 可见做法 | 真实效果 |
| --- | --- | --- |
| 直接拒绝 | 明说不能做、不愿做或不应做 | 边界最清楚，关系成本集中在当场 |
| 条件拒绝 | 缺材料、缺时机、缺授权、风险过高 | 给出可验证条件，也可能只是把拒绝推迟 |
| 降格办理 | 只给信息、只介绍、不背书、不催结果 | 保留一点帮助，同时限制连带责任 |
| 转正规路径 | 指向公开流程、书面申请或有权岗位 | 把私人压力移回制度，但不保证结果 |
| 延迟与冷却 | 不接关键问题、反复确认、错过窗口 | 让请求自然失效，代价是制造不确定性 |
| 中间人回绝 | 由递话者收回、改口或承担解释 | 保护资源方，也可能消耗中间人信用 |
| 交换式接受 | 明确或含蓄要求未来回报 | 请求成立，但人情账和控制关系加重 |

## 留面子不等于虚假同意

公开表态可以先保留对方体面，私下再给真实边界；但正文必须让读者看见有效结果。若人物口头“我看看”之后没有任何动作、回话或后果，作者应明确这是拖延、遗忘还是场景断链，不能把模糊自动解释成高明世故。

## 写作检查

- 拒绝者保护的是程序、资源、名誉、关系、时间还是自我边界。
- 请求者是否听懂；若没听懂，是经验不足、故意装不懂，还是中间人传话失真。
- 第三人在场是否提高了拒绝成本或提供了见证。
- 拒绝之后还有没有可执行的替代路径。
- 软拒绝是否在后续得到兑现，避免永远悬空。

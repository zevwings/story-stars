# 正向 B 场编排逻辑

> 本文件保存随项目固定的正向 B 场设计细节。触发方式、读取范围、dark 分流和产物路径由当前 runtime Skill 在解析 `$SPECIALTY_ROOT` 后执行。

## 核心推理链

生成 `design.b.md` 前, 按以下顺序判断:

1. **主文衔接**: 本场大纲与 `design.a.md` 给出的入戏点、场景功能和事后回接是否清楚。
2. **关系前提**: 这场是否属于明确同意、可拒绝、可停止、事后回稳的正向亲密。
3. **人数模式**: 先分双人 / 单主轴与多人轮换、协作或集体收束两类; 项目提供对应模板 (`design.b.solo.md` / `design.b.multi.md`) 时按其结构填, 未提供时按 SKILL 设计流程第 5 步字段清单生成。
4. **叙事功能**: 关系确认、状态反馈、情绪兑现、边界重置、承诺落地中, 本场主要承担哪一个；写清亲密不能代替解决的问题。
5. **现实约束**: 场域私密度、声音限制、时间预算、外部打断点、家具与退出路径是否明确。
6. **项目机制载体**: 若项目机制参与本场, 按项目 `$SPECIALTY_ROOT/mechanisms/` 与 `$SPECIALTY_ROOT/references/` 选择已经登记的承载方式。
7. **收束方式**: 场后如何退出玩法角色、回到主文，关系、身体、物件、现实安排或情绪余波落在哪里。

## 七幕设计重点

七幕是设计卡的执行编排层, 用于组织人物选择与状态变化, 不是机械填满流程。写后再按 [B 场 HD 节奏镜头](../../B场HD节奏镜头.md) 的五段宏观层检查整体压力曲线；两者映射与“攀升”同名异义见该规则页。

| 幕次 | 设计重点 |
|---|---|
| 起势 | 从 A 场临界点继续, 确认愿意与可停空间 |
| 定锚 | 明确主动权流动、称呼变化或关系边界 |
| 深入 | 推进亲密、身体或情绪的主要反馈 |
| 律动 | 建立节奏, 避免只剩重复动作 |
| 攀升 | 让状态、情绪或环境同步升高 |
| 高点 | 完成本场叙事目标, 不只追求热度 |
| 收束 | 回稳、照料、余温、主文承接 |

## 编排原则

- 每一幕都要服务本场叙事目标。
- 亲密动作、心理变化和环境变化要互相支撑。
- 多人场先逐关系确认当次权限，再逐人写参加理由、停止方式与场后位置。
- 多人场每一幕只设一个主要 POV；当前 POV 不得越级进入他人内心。
- 每幕记录全员位置和主要状态：主动参与 / 回应承接 / 观察旁观 / 暂停 / 照护 / 物理退场。
- 状态切换必须有触发点；暂停与退场人物不得凭空消失。
- 不使用固定“主攻 / 辅攻 / 承接”模板贯穿全场，位置随人物意愿与关系回摆变化。
- 环境、家具、声音与现实时间必须进入动作和节奏，不作空标签。
- 设计卡只写可执行指令, 不写成正文段落。
- 不另起平行 `outline.md` 真源。

## 禁止项

- 不用反派、药物、羞辱、束缚、身份落差或其他单项关键词替代项目场型判据。
- 不用身体反应倒推愿意。
- 不用“关系更近了”“机制完成了”替代具体后果。
- 不把所有角色写成同一种反应。
- 不为追求热度破坏人物边界、状态规则或主文承接。

# 亲密 HD 正文执行协议

> 本文件保存随项目固定的正向正文细节。触发方式、主入口、写入位置与是否回写主文由当前 runtime Skill 在解析 `$SPECIALTY_ROOT` 后执行。

## 目标
- 把 `design.b.md` 稳定落成 HD 18+ 正文。
- 保证与主文占位符前后文、人称、时态、事实一致。
- 让关系推进、情绪兑现、项目机制反馈都真正落地。

## 执行顺序

1. 先读 `design.b.md`，再写 `draft.md`；只有作者明确要求定稿时，再落 `final.md`。
2. 核对设计卡是否已经给出项目判据、人物授权、现实约束与停止通道；关键字段缺失时暂停，不自行补权限。
3. 按设计卡的主要 POV、人物位置、状态切换与环境限制扩写。
4. 完成限制解除、身份回归、场后照护与现实连续性。
5. 做质量自检并提示必要的后续同步项。

## 正文关注点

- 入场是否能从占位符跳来后立刻进戏。
- 节奏是否符合 `design.b.md` 的七幕推进与阶段变化。
- 感官、动作、心理是否互相支撑;同切片内是否完成感官重心轮转。
- 对话是否贴合角色关系和语言习惯。
- 收束后是否给出明确余韵与后续承接(让主文能接住余波,但正文不回写主文)。
- 项目专项机制是否严格继承设计卡与项目真源，并写清场后反馈。
- 私密度、声音预算、现实时间、家具、遮蔽物和外部打断是否真实进入动作与节奏。
- 多人场每一幕是否只跟一个主要 POV，旁观、暂停、照护与退场人物是否持续在场。
- 语言可能受限或失真时，非语言真意信号是否被正确识别，没有被改写成情趣推拉。
- 场景中是否有角色化的权力试探或情感对白，而非只靠泛化反应推进。
- 不缩水成 A 场长度。

## 强制写作约束

- **强制闭环**:每一段核心动作必须遵循:[动作] → [生理反馈] → [心理消解]。禁止纯动作流水账。
- **声音延迟策略**:在高潮或极致冲击点,采用"动作先发、声音延迟"的写法,强调失控感。
- **三秒静止法**: 当 `design.b.md` 中标出压拍点时, 用足量描写承住静止状态下的呼吸、视线、肌肉反应与人物判断, 制造停顿张力。

## 质量自检

- **对照准则**:对照 [亲密写前写后校验](../../亲密写前写后校验.md) 进行最终核对。
- **人物边界校验**:严禁出现与人物卡、亲密档案或动态状态冲突的反应、称呼、主动性或场后状态。
- **人设校验**:称呼、语气、主动性是否贴合本阶段关系?
- **演化校验**:对照角色关系卡亲密层与 `$SPECIALTY_ROOT/characters/` 露骨档中已登记的历程与偏好信息,熟练度与情感阶段未倒退或错位?
- **衔接校验**:是否严格依据 `design.b.md`,没有凭空补重大设定?
- **环境校验**:是否服从设计卡的空间、声音、时间、家具和退出路径，没有写成抽象场地?
- **多人校验**:主要 POV 是否稳定；暂停、旁观、照护与退场状态是否有动作和位置承接?
- **信号校验**:是否把非语言停止或降速信号误写成愿意或推拉?
- **身份回归校验**:协商玩法是否解除限制、恢复日常称呼并回到平等关系?
- **连续性校验**:身体、衣装、物件、空间和现实安排的变化是否按设计卡落地；普通损耗是否没有被自行升级为线索?
- **结果校验**:是否完成了关系、状态、情绪三条中的既定目标?
- **存储校验**:正文是否写到了正确路径?B 场未误回写主文?

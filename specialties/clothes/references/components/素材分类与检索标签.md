# 素材分类与检索标签

本文件定义 Story Stars 外部衣装素材的稳定检索分类。它服务图片、视频、截图组及其分析结果的定位与分流，不保存素材清单、抽帧状态、人物身份、实际衣物实体或人物衣装事实。

本文件不是第二份 catalog schema。`set | piece`、临时搭配、九种单件类型和穿着层级仍以 [衣装结构与穿着层级](衣装结构与穿着层级.md) 为唯一分类权威；catalog 的用途枚举、正文结构和写入门禁仍服从 [衣装收录协议](../../protocols/衣装收录协议.md)。

## 一、分类原则

每条稳定衣装观察分别判断以下内容，不能压入一棵互斥目录树：

1. **用途分类**：这件衣装主要为了什么穿用；使用一级加二级。
2. **结构分类**：画面中实际存在什么物理衣物；使用一级加二级，一条观察可以包含多个分件。
3. **辅助标签**：环境、视觉风格、露肤与透明度等可多选属性。
4. **实体粒度**：后续可能形成 `set`、`piece`、临时搭配或不形成实体；本文件不替代实体门禁。

分类标签只说明素材如何被检索，不证明衣装已经进入 catalog，也不证明项目角色拥有、穿过或偏好该衣装。

## 二、用途一级与二级

用途一级与 catalog 的八种受控用途一致。每个稳定 `view` 只记录一个主要用途候选；证据允许时可以记录兼容用途候选。无法判断时保留“未判定”，不得为了目录完整强行归类。

| 一级用途 | 中文 | 二级检索标签 | 典型边界 |
| --- | --- | --- | --- |
| `daily` | 日常 | 通勤、休闲、居家、学院、街头 | 描述日常公共或生活穿用，不表示衣物必然保守或低露肤 |
| `stage` | 舞台 | 拉丁演出、舞蹈表演、唱跳打歌、舞台主持 | 以表演、主持或舞台动态展示为主要目的 |
| `ceremonial` | 礼仪盛装 | 晚宴、婚礼、红毯、正式典礼 | 以隆重社交、仪式或礼仪展示为主要目的 |
| `cos` | 主题扮演 | 角色还原、幻想主题、主题制服、女仆主题 | 需要稳定角色、作品或主题身份；不是舞台的下级分类 |
| `sport` | 运动 | 健身、瑜伽、骑行、户外运动 | 以训练、竞赛或运动功能为主要目的 |
| `swimwear` | 泳装 | 泳池、海滩度假、温泉、水上运动 | 以涉水穿用或泳装结构为主要目的 |
| `action` | 行动 | 战术、功能制服、防护装备、行动机能 | 以行动、防护、职业功能或战术使用为主要目的 |
| `intimate` | 私密 | 情趣内衣、私密睡衣、束身吊袜、私密主题装 | 以私域展示、情趣互动或私密穿用为主要目的 |

二级标签只细化对应一级用途，不能改变一级用途的含义。一个素材同时具备舞台灯光和角色还原时，应依据主要穿用目的选择 `stage` 或 `cos`，另一项只能作为兼容用途候选或辅助说明。

## 三、结构一级与二级

结构一级沿用项目九种 `piece` 类型。二级是素材检索词，不新增 catalog `单件类型` 枚举。

| 一级结构 | 中文 | 二级检索标签示例 |
| --- | --- | --- |
| `top` | 上装 | 文胸、吊带、抹胸、衬衫、针织上装、胸衣式上装、外套、罩衫 |
| `bottom` | 下装 | 内裤、短裤、半裙、长裤、裙裤、围裹下装 |
| `dress` | 连衣裙 | 日常连衣裙、晚礼服、婚纱、睡裙、旗袍 |
| `jumpsuit` | 连体裤 | 长连体裤、短连体裤、连身工装 |
| `bodysuit` | 连体衣 | 时装连体衣、情趣连体衣、舞台 body、角色连体主体 |
| `swimsuit` | 一件式泳装 | 竞技泳衣、度假泳衣、冲浪连体泳衣 |
| `hosiery` | 袜类 | 短袜、长袜、大腿袜、丝袜、连裤袜、腿套 |
| `footwear` | 鞋履 | 高跟鞋、舞鞋、靴、运动鞋、凉鞋、拖鞋 |
| `accessory` | 配饰 | 腰带、手套、帽饰、眼镜、首饰、眼罩、穿戴式装饰 |

一条观察可以同时包含多个结构项，例如“拉丁演出服”可以拆成 `dress/舞裙`、`footwear/舞鞋` 和实际可见配饰。只看到局部时只记录可见分件，不补造完整造型。

非穿戴的武器、皮鞭、文件夹、乐器、捧花和布景不是衣装结构项；只有为了来源回查或解释展示语境确有必要时才进入备注。

## 四、内衣与 `intimate` 解耦

“内衣”描述结构、品类或贴身层；`intimate` 描述主要穿用目的。两者不能互相推出：

| 实际对象 | 结构观察 | 主要用途候选 |
| --- | --- | --- |
| 无痕文胸与基础内裤 | `top/文胸`、`bottom/内裤` | `daily` |
| 稳定配套的蕾丝胸衣、内裤与吊袜带 | 按实际分件记录 | 依据来源与设计目的判断 `intimate` 或其它用途 |
| 舞台鱼骨胸衣 | `top/胸衣式上装` | `stage` |
| 角色还原用单件 body | `bodysuit/角色连体主体` | `cos` |
| 高露肤比基尼 | 可见分件或稳定泳装套组 | `swimwear` |

露肤多、透明、蕾丝、紧身、深领或高开衩只能作为结构与视觉属性。它们不自动等于 `intimate`；反过来，低露肤或有外层覆盖也不排除私密用途。

判断顺序固定为：

```text
识别可见物理结构
  → 判断主要穿用目的
  → 记录环境、风格、露肤和透明度
  → 保留证据等级与不确定项
```

## 五、套组、单件与临时搭配

实体粒度服从项目分类权威，本节只说明素材标签如何进入后续判断：

- 文胸与内裤是两个物理独立核心分件，并且来源、共享纹样、配色、五金或设计关系证明稳定配套时，可以形成 `set` 候选。
- 文胸与内裤只是同一次穿着、没有稳定配套证据时，只是临时搭配；可以分别形成 `piece` 候选，也可以不建实体。
- 一个物理不可拆分的连体内衣不是 `set`，按实际结构候选为 `bodysuit` 或 `dress` 等 `piece`。
- 稳定套组默认先形成一个 `set` 候选；只有内部单件确有跨造型独立复用价值时，才额外形成独立 `piece` 候选。
- `set` 的主要用途仍按实际穿用目的判断。基础内衣套组可以是 `daily`，私密情趣套组可以是 `intimate`，舞台配套内衣式服装可以是 `stage`。

出现结构冲突、配套关系不清或只有文件名线索时，保留候选，不进入 catalog。

## 六、辅助检索标签

辅助标签允许多选，但不得写入 `clothes.catalog@2` frontmatter，也不得替代用途和结构判断。

| 维度 | 示例 | 边界 |
| --- | --- | --- |
| 环境 | 办公室、居家、卧室、舞台、泳池、海滩、户外、摄影棚 | 场景出现不自动改变衣装用途 |
| 视觉风格 | 古风、新中式、学院、街头、机能、复古、未来、甜美、冷艳 | 风格不等于用途；古风可以服务多个一级用途 |
| 露肤 | 低、常规、中、高 | 只描述可见覆盖范围，不推断授权或用途 |
| 透明度 | 不透、微透、半透、高透、无法判断 | 受灯光、肤色衬底、滤镜和压缩影响时必须降级 |

辅助标签后续可以由 `sm` 或索引工具输出候选值，但工具置信度不等于画面证据等级。

## 七、旧九类映射

旧的九类场景标签只能作为检索入口，不能继续充当互斥物理目录：

| 旧标签 | 新映射 |
| --- | --- |
| 日常通勤 | `daily`，再选择通勤、休闲、学院或街头等二级标签 |
| 晚宴礼服 | `ceremonial`；具体衣物仍按 `dress`、`set` 或其它实际结构判断 |
| 私密情趣 | 依据穿用目的判断 `intimate`；卧室和露肤度改为辅助标签 |
| 泳装水浴 | `swimwear`；泳池、海滩、温泉等进入二级或环境标签 |
| 古风新中式 | 进入视觉风格，不独占用途分类 |
| 舞台演艺 | `stage`，再选择拉丁演出、舞蹈表演、唱跳打歌或舞台主持 |
| 角色还原 | 有稳定角色或主题身份时为 `cos` |
| 运动户外 | 拆分为 `sport` 用途和户外环境；普通户外服不自动归运动 |
| 战术制服 | 依据实际功能判断 `action`，制服、战术或机能作为二级或风格标签 |

## 八、维护边界

- 本文件只维护稳定分类语义，不记录源文件数量、素材路径、模型版本、抽帧命令、批次进度、复核队列或错误清单。
- 新增一级用途或一级结构前，必须先核对 Clothes Specialty schema 和项目唯一分类权威，不能在本文件单方面扩展。
- 新增二级标签必须说明所属一级、观察边界和至少一个易混项；同义词优先作为检索别名，不重复创建正式标签。
- 分类规则变化不能静默重写既有 `CLO-*`。受影响实体必须另行盘点、复核并按项目变更流程处理。
- 实施细节、候选结果和未闭合判断留在 `.analysis`；catalog 只接收已经通过当前协议与收录门禁的完成实体。

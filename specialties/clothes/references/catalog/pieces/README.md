# 基础衣装单元（Pieces）

`record_kind: piece` 表示可独立维护与复用的基础衣装单元，不限定为一件物理衣物。原生配套内衣、泳装可以各用一个 CLO 记录上下装等内部组成，不拆成多个档案，也不为相同对象另建 Set。

返回 [Catalog 说明](../README.md) 或 [基础单元索引](_index.md)。分类权威见 [衣装结构与穿着层级](../../components/衣装结构与穿着层级.md)，内容要求见 [衣装档案写作规范](../../components/衣装档案写作规范.md)。

## 九类基础单元

分类表继续使用 `单件类型` 字段与既有九类枚举；本页中的“单元”不引入新字段。

| 类型 | 收录范围 | 边界 |
| --- | --- | --- |
| [top](top/_index.md) | 衬衫、背心、胸衣式外穿上装、外套、罩衫 | 内衣归 `bodysuit`；泳装归 `swimsuit` |
| [bottom](bottom/_index.md) | 裤、半裙、围裹式下装 | 内裤归 `bodysuit`，泳裤归 `swimsuit`；普通沙滩围裙仍按下装判断 |
| [dress](dress/_index.md) | 连衣裙、旗袍、单件礼服、睡裙 | 分体上衣＋半裙不能因搭配成套合写为 `dress` |
| [jumpsuit](jumpsuit/_index.md) | 上下身连续且有分离裤腿的连体裤装 | 紧身外穿或运动连体裤不自动成为内衣 |
| [bodysuit](bodysuit/_index.md) | 独立内衣、塑身衣、贴体连体衣与原生配套内衣 | 原生文胸＋内裤属于一个基础单元；详见 [内衣与泳装边界](#内衣与泳装边界) |
| [swimsuit](swimsuit/_index.md) | 连体泳衣、独立泳装上衣或泳裤、原生配套比基尼 | 原生上下泳装作为一个单元，不重复建立 `sets/swimwear` 档案 |
| [hosiery](hosiery/_index.md) | 丝袜、连裤袜、长短袜、腿套 | 不将任意袜类与其他衣物的搭配合写成一个 Piece |
| [footwear](footwear/_index.md) | 鞋、靴、凉鞋、拖鞋 | 一双鞋按通常使用单元维护，不拆成左右档案 |
| [accessory](accessory/_index.md) | 包、腰带、首饰、手套、帽饰等 | 衣物不可拆卸的装饰不另建实体 |

## 判定顺序

1. 确认实际对象与证据。来源只有独立文胸或泳裤时，不虚构完整配套。
2. 若为独立衣物，或有原生稳定配套依据的内衣／泳装，按一个 Piece 判断独立维护价值。
3. 原生内衣归 `bodysuit`，原生泳装归 `swimsuit`；其余按基础单元结构归类。内衣、泳装的多部件例外不扩展到任意上装＋下装组合。
4. 若对象含多个基础单元，按 [Set 准入](../sets/README.md) 判断稳定整体身份；普通临时搭配不建新实体。
5. 分别判断主要用途、兼容用途与穿着层级。颜色、紧身或露肤程度不能替代用途判断。

## 内衣与泳装边界

- 紫色蕾丝文胸＋原生配套内裤：一份 `piece + bodysuit`，在“结构与使用”中描述两个部件与配套依据。
- 原生比基尼上下装：一份 `piece + swimsuit`；一件式泳衣同样属于本类。
- 同色、同图或一次穿着不能证明原生配套；不确定时保留候选，不强行合并。
- 偶尔仅穿内部一个部件，不新增 CLO；实际采用时在 owner 写清采用范围。已有独立部件与整体记录重叠时，核对来源、身份和引用后另行处理，不自动合并或删除。
- `bodysuit` 保留时装 body、体操服及无独立裙摆或分离长裤腿的单件 COS 主体归口；它们不因此成为内衣或 `intimate`。
- 紧身外穿服和运动连体裤不自动归内衣。睡裙归 `dress`，袜类归 `hosiery`；普通罩衫、草帽、围裹裙不因用于沙滩成为泳装。

## 与整体装束的关系

原生内衣或泳装本身作为基础单元维护，不再到 `sets/daily`、`sets/intimate`、`sets/swimwear` 建立相同实体。基础单元与外衣、鞋履或配饰形成稳定更高层身份时，才考虑 Set；后者必须有额外的整体身份，不能只换标题复制 Piece。

基础单元内部组成使用普通段落或列表写入 `## 结构与使用`，说明各部件、配套依据、穿脱关系和使用边界；不新增 Piece 不支持的 `## 组成` 或 H3。

## 档案结构速查

文件名、frontmatter 与 H1 使用同一实际 ID；frontmatter 仅包含 `schema: clothes.catalog@3`、`id`、`record_kind: piece`。实际生成与校验以锁定公共协议为准，不复制占位 ID 作为实体。

正文按以下顺序组织：

1. `## 分类`：一张两列表，必填 `单件类型`、`搭配方式`、`主要用途`；存在兼容用途时才增加该行。搭配方式使用 `standalone | required | optional`。
2. `## 搭配要求`：按实际内容使用 `### 必需角色`、`### 可选角色`、`### 约束`，每节一个非空列表。`required` 必须有必需角色；三节均无内容时省略整个 H2。
3. `## 来源与边界`：区分直接观察、文档明示、不确定观察和项目设计，不把不可见结构或材料推断写成事实。
4. `## 结构与使用`：说明当前基础单元及其内部部件的结构、色材、固定、穿脱与活动条件。
5. `## 使用条件与叙事作用`：说明季节、环境、功能和适用边界。
6. 主用途或兼容用途包含 `intimate` 时，追加 `## 张力与互动语法`；不因位于内衣目录自动触发。
7. 实际采用内容已自足写入正式 owner 并完成校验后，末尾追加 `## 正式去向`，只保留一个非空、不重复的项目相对路径列表。

不添加公共协议未定义的 frontmatter 字段或 H2/H3，不保留空标题和占位内容。

# 衣装收录与状态协议

## 写入门禁

只有作者明确要求“收录”“建档”“更新 CLO”“拆成项目组件”或目录查重时才写项目参考。写入前必须确认 `$CLOTHES_ROOT` ready；未配置、禁用、缺包、版本冲突或其它 blocking 状态全部停止目录操作。

## 稳定 ID

- ID 使用 `CLO-0001` 形式，不编码用途、部件类型或名称。
- 文件名使用 `CLO-0001_名称.md`；名称变化不改变 ID。
- 分配新编号时扫描 `references/catalog/` 下全部文件和索引，以当前最大数字加一；写入前再次扫描。`0.0.2` 不支持并发分配，同一项目的 catalog 写入必须串行。
- 发现重复 ID、同一 ID 多实体或同一实体多分类时停止，不自动覆盖或合并。

```yaml
pairing: standalone | required | optional

  required_roles: []
  optional_roles: []
  constraints: []
status: reference_only | analyzed | adapting | candidate_ready | transferred | retired
formal_targets: []
```

这些字段是 Markdown 内容契约，不是独立事实数据库。每个档案仍须用正文自足说明来源、观察／推断边界、结构、颜色、材质、使用条件和叙事用途。

## `intimate` 附加内容

当 `primary_use` 或 `compatible_uses` 包含 `intimate` 时，档案正文必须增加“张力与互动语法”，至少说明：

- 核心张力与主要材质反馈；
- 一条主导互动路径，例如隔料抚摸、缓慢褪下、保留穿着或一次性撕裂；
- 互动后的衣物结果：完整、位移、脱下或损耗；
- 撕裂若成立，具体可损耗分件、预设薄弱点、皮肤保护和替换／报废条件；若不成立，明确不以撕裂实现张力；
- 本档只描述衣物可承载的设计路径，不替人物建立稳定偏好，不替任何场次决定实际动作。

同一档案可以说明一条主路径和一条克制的替代路径，但不得机械罗列所有动作。丝袜、蕾丝、系带等材质或结构不自动等于撕裂、束缚或服从。

## 状态

- `reference_only`：保存了可回查参考，尚未完成结构分析。
- `analyzed`：完成拆解，尚未进入具体适配。
- `adapting`：正在为人物或场景改造。
- `candidate_ready`：候选规格完整，但尚未写入正式 owner。
- `transferred`：确认内容已自足写入至少一个正式 owner；必须记录存在的 `formal_targets`。
- `retired`：不再活跃采用，保留去重、避错或历史价值。

状态只表示参考工作流，不表示故事事实。迁移既有目录时保留原 ID 和状态，不批量升级或重命名。

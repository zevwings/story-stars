# 章节模板说明

> 本目录只负责章节包模板骨架。模板存在不代表章节已经发生, 也不得被当作正式章节事实。

## 文件职责

- `outline.md`: 本章结构真源。`本章目标` 定义任务，`本章行动与结果` 简述全章因果与人物落点，`关键场景` 展开具体动作、反馈和实际选择，`后续牵引` 汇总章末状态与承接；信息边界、角色、正式来源与创作抓手各归对应区块。引用设定、引用线索与上下文、回收安排和硬边界按实质内容保留，空栏目与模板说明不进入成品。真实绝对边界全部保留，不按数量截断。
- `draft.md`: 正文草稿, 可以反复修改, 不自动进入定稿。
- `revision.md`: 修订记录或修改说明, 不替代大纲、正文或摘要。
- `summary.md`: 项目内唯一完整定稿摘要模板；使用 `chapter.summary@3` 的紧凑 frontmatter 绑定同章 `final.md`，正文以结构化 Markdown 同时承载人类摘要和确定性检索输入。不再存在第二份公共摘要格式或同级 `summary.yaml`。

## 使用方式

- 新建章节包时, 复制需要的模板文件到目标章节目录。
- 章号、目录名和状态必须同步登记到 `chapters/_index.md`。
- `summary.md` 只由 `chapter-finalizer` 在定稿或补录摘要时创建、更新；`final_source_hash` 必须是当前 `final.md` 完整字节的 64 位小写 SHA-256。
- frontmatter 只允许 `schema: chapter.summary@3` 与 `final_source_hash`。章号由章节索引和目录定位、`final` 状态由该文件的定稿职责表达，不在文件中重复维护。
- `核心摘要` 必须存在且包含自然语言摘要。`检索标签`、`本章变化`、`后续接口` 仅在有实际内容时写入；没有内容时删除整个小节，禁止保留空表、占位行或空数组。
- 正文只能保留一个已替换章号的 H1，且必须位于全部 H2 之前；二级栏目按模板顺序出现。禁止 H3、栏目外正文、额外表格、第二张表格及任何 `<...>`、`chXXX`、`第 XXX 章` 或模板说明文字。
- `检索标签` 的类型只允许角色、地点、势力、物件、机制、场景、情绪；`本章变化` 的类型只允许剧情线、线索、人物状态、关系、知情边界、设定、机制。剧情线变化只使用推进/收束，线索变化只使用埋设/暗示/揭示/解决。
- `source_path`、`source_hash`、章号和 generated schema 由 builder 派生，不写入正式文件。正文二级标题和表头属于 `chapter.summary@3` 协议，不得任意改名或增加未知栏目。
- 若只需要大纲, 停在 `outline.md`; 临时试排、备选走法和未确认展开进入 `.prewrite/` 或 `.analysis/`；项目启用 `construction` 后，作者已确认且写作时必须继承的执行规格才进入配置的施工真源。

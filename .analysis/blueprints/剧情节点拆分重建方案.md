## 二、重建目标

重建后的单个正式节点只承担一个可独立完成的长期变化：

1. 只有一个主要状态变化。
2. 可以独立进入 `pending → active → completed`。
3. 完成判据可以同时满足，不需要等待另一条独立事实。
4. 只有一个归档主体；共享事件由不同线路记录各自的 `本线变化`。
5. 只连接直接因果上游和下游。
6. 场次、动作、对白、衣装、章号和身体流程留在 `story/construction/`。

判断门禁：

> 如果 A 已经发生，而 B 仍可能不发生，A 与 B 必须拆成两个正式节点。

预计结果：

- 理论拆分上限：约 255 个节点。
- 跨文件去重后的合理目标：约 235—245 个节点。
- 不追求数量本身；若拆出的内容没有独立完成状态，则退回施工层。

## 十、ID 与替代规则

正式迁移时：

1. 不复用旧节点 ID 表示新的不同事实。
2. 拆出的每个节点取得新的全局唯一 `PL-M/S/I-NNN`。
3. 旧复合节点进入 `_status/retired.md`。
4. 旧节点的“替代接口”列出全部新节点。
5. 新节点全部登记为 `pending`，不因拆分自动进入 `active` 或 `completed`。
6. 施工单元接口从旧节点重映射到实际服务的新节点。
7. 章节大纲尚未消费时，不保留兼容别名或第二份正式正文。

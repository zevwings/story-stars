# 角色生图公共能力实现方案

> **状态**：2026-08-08 已确认 MVP 边界；本文是实施蓝图，不代表代码、仓库或图片已经创建。
>
> **目标**：在公共 `story-writer` 中提供两个题材中立的角色生图 Skill，先验证“正式角色卡 → 稳定脸型 → 不同场景仍是同一人”的最短闭环。
>
> **真源**：人物事实仍以项目 [`BIBLE.md`](../../BIBLE.md)、[`characters/`](../../characters/_index.md) 和人物正式卡为准。批准图片只是视觉生产基准，不反写故事正典。
>
> **旧原型**：`intimacy-visuals` 只提供资产组织与失败经验，不是可直接移植的程序库，不整体复制进 `story-writer`。

## 一、MVP 结论

```text
character-identity-builder
主卡 + 形象卡
→ 4 张正脸候选
→ 作者选择 primary_face
→ 五视图 + 两张跨场景测试图
→ 作者批准 identity v1

character-image-generator
已批准 identity
+ 当前形象/衣装卡
+ 作者自然语言请求
→ 展示实际 Prompt
→ Prompt-only 或原生 ImageGen
→ 作者选择并归档成图
```

两个 Skill 以“已批准 identity”为稳定边界：

- `character-identity-builder` 决定“这个人是谁”；
- `character-image-generator` 决定“这个人出现在哪个画面”；
- 两者必须由作者分别触发，不自动串联；
- 场景生成不得重新设计角色的脸。

首轮试点固定为正式角色 `F-06-苏晚乔`。成功标准：五视图、两张验证图和一个独立普通场景均被作者判断为同一人，且整条链不修改 `characters/`、不自动 commit/push。

## 二、不进入 MVP

- Body Pack；
- Look Pack、Style Pack 生命周期；
- 多角色正式场景；
- 自动脸部相似度阈值和自动批准；
- Job / Run / Attempt / Candidate 通用状态机；
- Provider HTTP adapter、认证和计费重试；
- `sw visual ...` CLI；
- 局部蒙版修复和 lineage；
- source drift 自动传播；
- alias 迁移和模糊搜索；
- 批量导入、批量生成和无人值守任务；
- LoRA、ControlNet 或专用身份模型训练。

延期不等于取消。同一角色未来可以拥有多个 Look Pack，但它们不应阻塞第一张稳定脸的建立。

## 三、公共边界

### 3.1 角色资格与解析

正式 identity 只绑定到：

- 人物注册表中唯一登记的角色；
- `characters/major/` 或 `characters/minor/`；
- 已存在 `主卡.md` 和 `形象.md`。

`character-image-generator` 在需要补全衣装时读取 `衣装.md`。作者明确给出临时衣装时可以生成，但不得把它宣称为正式事实，也不得违反人物卡禁区。

`characters/preentry/` 不创建正式视觉资产；MVP 也不实现 ad hoc 图片晋级。

解析只支持角色 ID 或正式姓名的精确唯一匹配。错字、别名、包含匹配或重名一律要求作者改用正式 ID。

目录名由注册表自动派生：

```text
<character-id>-<canonical-name>
```

例如 `F-06-苏晚乔`。作者不得手写 ID 与姓名组合；当前项目 `M-19` 对应曲修远，并非冼泠漪。

### 3.2 正典与隐私

- Skill 只读本次所需人物卡，不把完整章节、关系档或无关秘密交给图片模型；
- 模型补出的细节不成为人物事实；
- 批准图片不自动修改 `主卡.md`、`形象.md` 或 `衣装.md`；
- 正式外貌或衣装边界要修改时，转交 `character-builder`；
- `visuals/` 是视觉生产记录，不进入故事真源层级。

## 四、`character-identity-builder`

### 4.1 职责

```text
story-writer/skills/character-identity-builder/SKILL.md
```

负责解析角色、读取主卡和形象卡、提炼脸部约束、调用当前 Agent 的原生 ImageGen、组织两次作者决策并在批准后落盘。它不生成普通场景成品、不创建 Look Pack、不修改人物卡。

### 4.2 卡片提炼

Skill 展示一段简短提炼摘要后直接生成候选，不先让作者填写或确认“脸部参数表”。只有正式卡冲突或决定性信息缺失时才暂停提问。

identity 固定：

- 骨相和脸部轮廓；
- 眼、眉、鼻、唇；
- 肤色、瞳色、自然发色、发际线；
- 稳定标记和外观年龄感。

identity 不固定：发型、妆容、首饰、发饰、服装、表情和光线。

### 4.3 基线

苏晚乔纵切采用高细节半写实数字插画：写实面部比例、自然皮肤纹理、电影感柔光；不做真人摄影或夸张二次元。身份图使用 `1:1`，测试图默认 `4:5`；manifest 记录实际像素，不写死分辨率。

### 4.4 第一次决策：主脸

- 每轮生成 4 张独立正脸，不从模型拼版裁切；
- 四张共享人物硬约束，只在未规定的次级骨相上形成差异；
- contact sheet 只供人审阅，不是机器参考或权威资产；
- 作者明确选定一张后，原图直接成为 `primary_face` 和 `front.png`；
- 禁止再次“优化重画”正脸；仅允许非生成式格式转换或尺寸规范化。

### 4.5 五视图

```text
front
left-45
right-45
left-profile
right-profile
```

`front` 就是选中的原图，其余四张分别以它为身份参考生成。五视图使用统一中性条件：肩部以上、浅灰背景、均匀柔光、长发简单束起并露出耳部和下颌线、无首饰发饰和明显妆容、素色圆领上衣、放松的中性表情。

### 4.6 第二次决策：完整 identity

最终批准前固定生成：

1. 日间健身房，中近景，高马尾、清爽训练装、自然明亮的笑；
2. 夜间城市街头，腰部以上、自然散发、朱红短外套、认真神情，脸朝镜头约 45°。

两张图主动改变发型、衣装、表情和光线，验证锁定的是脸。作者一次审查“五视图 + 两张测试图”后批准 `identity v1`；测试不得放在批准之后。

失败处理：

- 单张漂脸：只重生成该图；
- 多张漂脸：返回正脸候选阶段；
- 每阶段最多修正两轮；
- 两轮仍失败则暂停诊断，不自动继续消耗生成次数；
- 批准前所有文件只留在忽略区。

## 五、`character-image-generator`

### 5.1 职责与用法

```text
story-writer/skills/character-image-generator/SKILL.md
```

作者只用自然语言描述画面，例如：

> 生成苏晚乔在健身房结束训练后喝水的中近景，傍晚光线。

Skill 自动读取当前批准 identity、`形象.md`、与场景相关的 `衣装.md`，编译并展示实际 Prompt。只有请求明显冲突正式设定时才提问。

触发规则：

- “只生成 Prompt”：展示后停止；
- “生成图片”：当前 Agent 在当前会话直接调用原生 ImageGen；
- 意图不清：生成前询问一次；
- 不创建另一个 ChatGPT 会话；
- ImageGen 不可用时只返回 Prompt 和参考图清单，不伪造成功、不切换自建 adapter；
- 纯网页会话可生图但不能自动写本地 submodule，需后续显式导入。

### 5.2 参考图

每次最多输入两张身份图：

| 目标角度 | 参考图 |
| --- | --- |
| 正面或近正面 | `front` + 最接近方向的 `45°` |
| 45° | `front` + 对应侧 `45°` |
| 侧脸 | `front` + 对应侧 `profile` |

`front` 始终是主身份源；validation 图片永远不作为机器参考。禁止每次把五视图全部塞给模型。

### 5.3 Prompt 与候选

`request.md` 保存作者可读的中文语义请求；`prompt.md` 保存实际发送给 ImageGen 的完整 Prompt。Prompt 区分 identity 硬约束、画面要求、卡片补全项、禁止漂移项和构图光线。

只要求 Prompt 时默认不落盘；作者明确说“保存这个 Prompt”才写指定文件。

普通场景规则：

- 默认 `4:5` 竖幅，作者可明确覆盖；
- 默认生成 2 张候选；
- 作者可以接受 0、1 或 2 张；
- 多张保存为 `image-01.png`、`image-02.png`；
- 只有接受的图片及其 request/prompt/manifest 进入稳定历史。

## 六、项目配置

视觉能力不做可删除 feature module。现有 module remove 会删除所拥有的目标目录，不能让模块生命周期拥有作者批准资产。

项目根 `.story.config.toml` 增加：

```toml
[visuals]
metadata_root = "visuals"
asset_root = "visual-assets"
```

规则：

- `[visuals]` 存在即启用，不增加 `enabled = true`；
- `story-writer` 不假设 `asset_root` 一定是 submodule；
- `story-stars` 将它指向图片 submodule；
- 不新增 `.visuals` 或第二份配置；
- 两个值只能是项目内安全相对路径；
- 拒绝绝对路径、`..`、项目根、`.git` 和 symlink 逃逸；
- Skill 可创建约定内子目录，但不初始化远端、submodule 或 Git LFS。

## 七、存储布局

### 7.1 写作库：文字记录

```text
story-stars/
  visuals/
    README.md
    characters/
      F-06-苏晚乔/
        identity/
          current.json
          v1/
            request.md
            prompt.md
            manifest.json
        renders/
          20260808T143012-训练后喝水/
            request.md
            prompt.md
            manifest.json
```

`visuals/` 进入主仓历史，但不复制全分辨率图片。

### 7.2 图片仓库

规划建立 private 仓库：

```text
git@github.com:zevwings/story-stars-visuals.git
```

挂载为 `story-stars/visual-assets/`，使用 Git LFS 管理 `png`、`jpg/jpeg`、`webp`。本文不创建远端。

```text
visual-assets/
  .workspace/                         # Git 忽略，未批准候选
  approved/characters/F-06-苏晚乔/
    identity/v1/
      front.png
      left-45.png
      right-45.png
      left-profile.png
      right-profile.png
      validation/
        gym-daylight.png
        street-night.png
    renders/20260808T143012-训练后喝水/
      image.png                        # 或 image-01.png / image-02.png
```

validation 图片作为批准证据保留，但不是生成参考。

### 7.3 批准与 Git

“批准 identity v1”授权 Skill 在本地把七张图复制到 `approved/`，写入 request/prompt/manifest，并原子更新 `current.json`。普通场景只在作者接受候选后落盘。

Skill 不执行 `git add`、commit、push、GitHub 仓库创建或 submodule 初始化。人工提交顺序固定为：

```text
先提交并推送 visual-assets
→ 再提交 story-stars 的 visuals/ 与 submodule gitlink
```

manifest 不重复记录 submodule commit；主仓 gitlink 已承担该职责。

## 八、最小记录协议

### 8.1 `request.md` / `prompt.md`

`request.md` 保存原始请求、卡片提炼摘要、画风画幅和禁止项，不复制完整人物卡。`prompt.md` 保存实际 ImageGen Prompt；identity 多次调用时按最终获批资产分节记录，不归档被拒绝候选的长篇运行历史。

### 8.2 `manifest.json`

只保存角色、版本、批准时间、正式卡路径/hash、资产路径/hash/尺寸：

```json
{
  "schema_version": 1,
  "character": {"id": "F-06", "name": "苏晚乔"},
  "identity_version": 1,
  "approved_at": "ISO-8601 time",
  "primary_asset": "front.png",
  "sources": [
    {"path": "characters/major/苏晚乔/主卡.md", "sha256": "..."},
    {"path": "characters/major/苏晚乔/形象.md", "sha256": "..."}
  ],
  "assets": [
    {
      "role": "front",
      "path": "approved/characters/F-06-苏晚乔/identity/v1/front.png",
      "sha256": "...",
      "width": 1024,
      "height": 1024
    }
  ]
}
```

其余四视图和两张 validation 图同样登记。render manifest 沿用基础结构并增加 `render_id`。

MVP 不记录 run/attempt/candidate 状态、provider request id、lineage 图、许可表或未校准的相似度分数。`approved_at` 和正式 manifest 表示作者已经批准；候选区没有 manifest。

### 8.3 `current.json`

```json
{
  "schema_version": 1,
  "identity_version": 1,
  "manifest": "identity/v1/manifest.json"
}
```

批准版本不可变。以后创建 `v2`，批准后只移动 `current.json`；回滚同样只移动指针。

## 十、测试与验收

### 10.1 配置

在 `apps/sw/tests/cli.rs` 覆盖：

- 旧项目没有 `[visuals]` 仍通过；
- 合法相对路径通过；
- 未知字段、绝对路径、`..`、项目根、`.git`、逃逸 symlink 失败；
- `asset_root = "visual-assets"` 可以指向 submodule 工作树。

### 10.2 Skill 前向测试

- `F-06` 与 `苏晚乔` 均能精确解析；
- preentry、别名、错字和歧义名称必须停止；
- Prompt-only 不调用 ImageGen、不自动落盘；
- 生图必须读取批准 identity；
- 没有 ImageGen 时诚实回退 Prompt-only。

### 10.3 苏晚乔纵切

- 四张正脸候选均为独立文件；
- 选中原图直接成为 `front.png`；
- 其余四视图与两张验证图被作者判断为同一人；
- 身份图没有白梅发扣、红衣或明显妆容等 Look 泄漏；
- 最终批准前没有图片进入 `approved/`；
- 批准后七张图、source hash、asset hash 和 current 指针完整；
- `characters/` 无改动，两个仓库均无自动提交。

首轮只做人审同人判断。旧原型中部分女性参考板脸部结构高度近似，不能把旧图数量当成“跨角色不撞脸已经成立”的证据。

## 十一、实施顺序

1. **公共 MVP**：配置 schema/tests、两个 Skill、路由文档；不调用真实 ImageGen。
2. **项目存储**：创建 private 图片仓库、LFS、submodule 与项目配置。
3. **苏晚乔纵切**：完成两次人工决策并保存 identity v1。
4. **独立场景**：手动触发 generator，验证 Skill 边界和身份复用。
5. **证据驱动扩展**：根据真实漂脸和操作摩擦决定 Look/Style/Body Pack、`sw visual`、drift、import、自动 QC、多角色或更强后端。

## 十二、主要风险

- **ImageGen 不保证绝对锁脸**：两轮仍明显漂脸时暂停并评估后端，不继续堆 Prompt。
- **Look 泄漏**：身份图必须保持中性；示例参考板只借结构，不照搬华丽发饰和衣装。
- **两仓失配**：图片仓先提交，主仓后提交；提交前人工核对 hash 与路径。
- **平台能力不同**：有原生 ImageGen 就调用，没有就 Prompt-only，不提前开发 adapter。
- **MVP 不自动 stale**：manifest 保存 source hash；再次生成时发现变化只提示作者，完整 drift 生命周期延期。

## 十三、完成定义

- 公共层存在两个独立 Skill；
- `[visuals]` 向后兼容且路径安全；
- 未新增 CLI、provider adapter 或状态机；
- 文字记录与图片分仓；
- `F-06-苏晚乔` 有作者批准的 identity v1；
- identity 含五张权威参考图和两张验证图；
- generator 按角度最多选择两张身份参考；
- Prompt-only 不自动落盘，图片生成不自动提交；
- 作者是批准的唯一主体；
- 生图结果不修改人物正式真源。

```text
正式人物卡
→ character-identity-builder
→ 主脸选择
→ 五视图 + 两张验证图
→ 作者批准 identity
→ character-image-generator
→ Prompt 或候选图
→ 作者接受
→ 文字与图片分仓归档
```

实现完成后，以 `story-writer` 源码、Skill、配置 schema 和项目 manifest 为执行真源；本文转入 `.analysis/archived/`，不继续作为第二套运行规范。

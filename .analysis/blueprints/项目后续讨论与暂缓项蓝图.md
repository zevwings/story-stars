## 二、后续统一讨论议题

### 1. 晏林的阶段一主动目标与阻力

当前人物动态状态仍缺少可直接驱动开篇选择的“主动目标—现实阻力—失败代价”闭环。后续讨论需要先回答：

- 晏林在第一案发生前主动追求什么，而不是只等待异常进入生活；
- 这个目标怎样与心理咨询工作、管理局边界和亲密主调同时发生作用；
- 哪个现实阻力会迫使他作出有代价的选择；
- 该目标如何跨越至少数章，而不是在第一案中一次性解决。

讨论完成前，不填 `context/characters/晏林.md` 的待定字段，也不把候选答案写进正式剧情节点。

### 2. 开篇顺序与第一批章节闭环

需要在同一次讨论中确定：

- 是否使用锦云山楔子，以及楔子与 `YL-001—YL-003` 的实际阅读顺序；
- 第一章的单一视角、章目标、章尾变化和最小节点消费范围；
- `CON-0013`、`CON-0037` 如何按章节消费边界拆分，避免一个施工单元横跨多阶段；
- outline → construction bound → draft → review → final → state write-back 的第一轮验收标准。

### 3. 阶段四、阶段五容量复核

正文闭环至少运行一轮后，再用实际章长、出场密度和读者负荷复核：

- 哪些节点是真正的长期状态变化，哪些只应留在施工层；
- 哪些人物接口承担重复功能，可以合并、降级或退役；
- 犯罪线是否挤压亲密主调，责任轴是否仍能分别证明、分别收束；
- 终局“解释权”需要落到哪些可观察的制度对象，而不是抽象口号。

## 三、讨论顺序

1. 先确认晏林阶段一主动目标与阻力。
2. 再确认楔子和 `YL-001—YL-003` 的阅读顺序。
3. 然后拆开篇施工、绑定单章并完成第一轮正文闭环。
4. 最后以正文试运行数据复核阶段四、阶段五，不提前做全库压缩。

前三项存在依赖关系，不建议拆成互不知情的多轮局部修改。第三项以真实正文反馈为输入，当前继续暂缓。

## 四、R3 工具状态

- 实时状态入口：[`scripts/project-status.sh`](../../scripts/project-status.sh)。默认只读，不在蓝图中手工保存节点数、章节数或 Git dirty 数。
- Timeline 刷新：运行 `scripts/project-status.sh --refresh-timeline`，只重建并校验 Timeline GraphRAG，然后输出最新状态；它不刷新会映射当前人物候选的其他 RAG source 域。
- Timeline GraphRAG 只接受 `story/timeline.md` 中 `- chNNN: ...` 形式的“已定稿／下一节点”。当前没有已登记章节，因此 `0 events` 是合法 `idle`，不能把季度结构表改造成虚假章节事件。
- 第一份正式章节或下一节点按工具契约登记后，刷新命令应自动把 timeline 状态转为 `ready`；若已有 `chNNN` 目录但仍为 `0 events`，状态脚本标记为 `attention`。
- 已安装的 `sw 0.0.1` 运行 `sw check config` 时会把项目现用的顶层 `[visuals]` 误报为未知键；`sw check rag`、timeline、剧情线和施工校验不受影响。不能通过删除有效视觉配置规避，应在 story-writer runtime 的 config allowlist 中另行修复。

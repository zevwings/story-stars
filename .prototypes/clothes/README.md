# 服装原型库

本目录保存服装的已收敛视觉结论、结构拆解、采用边界与候选定制方案。它属于 `.prototypes/` 持久原型参考层，不是故事事实、人物衣柜真源或场次施工规格。

## 职责边界

- 保存 COS 以及按日常、舞台、礼仪正装、情趣、运动、泳装和行动用途归档的服装原型。
- 区分官方明示、创作者文案、视觉对应、项目推断与尚未确认项。
- 记录色彩、轮廓、分件、材质观感、动态、承重、穿脱、收纳和现实制作问题。
- 可以登记候选人物或候选用途，但不得由服装反推人物身份、剧情关系、亲密授权或正式场次。
- 作者确认后的稳定人物衣装重新写入 `characters/<人物>/衣装/<服装名>.md` 并登记到 `_index.md`；只有跨衣装稳定成立的审美与组合语法才写入 `_GRAMMAR.md`。绑定剧情节点后的场次执行规格重新写入对应 `CON-*`。正式文件不得依赖本目录。

## 目录模型

服装按主要身份或用途进入分类目录；每套可独立辨认、改造或分配的服装使用一个稳定编号和一份实体文件：

```text
clothes/
├── cos/
│   ├── README.md
│   ├── _index.md
│   └── CLO-0001_作品-角色-造型.md
├── daily/
├── stage/
├── ceremonial/
├── intimate/
├── sport/
├── swimwear/
├── action/
├── _index.md
├── _template.md
└── README.md
```

- 每个 `CLO-*` 只有一个实体位置，不因兼容用途复制到多个目录。
- 主归类顺序为：明确作品或角色复刻进入 `cos/`；其余衣装按主要使用场景进入 `daily/`、`stage/`、`ceremonial/`、`intimate/`、`sport/`、`swimwear/` 或 `action/`。
- 现实成衣、原创定制和混合参考都写入“来源类型”，不单独建立主归类；社交与职业场景写入“兼容用途”或衣装档正文。
- 同一视觉身份的轻度改造留在原文件内；轮廓、用途或核心部件已变化到可独立采用时，新建 `CLO-*`。
- 固定类型目录全部预建，即使当前没有条目也保留 `README.md` 与 `_index.md`。`README.md` 定义准入边界，`_index.md` 只登记当前目录内的衣装。
- 根 `_index.md` 只路由各类型 `_index.md`，不直接登记 `CLO-*`。
- `CLO-*` 只用于原型库内部识别，不写入正式人物卡、剧情节点、施工单元或正文。

## 采用与转译

- 稳定拥有且会跨场调用的具体衣装，将已确认规格重新写入 `characters/<层级>/<人物>/衣装/<服装名>.md` 并登记到 `_index.md`；不要把具体库存塞进 `_GRAMMAR.md`。
- 只服务某个正式节点的衣装，将当场执行规格重新写入对应 `CON-*`。
- 转译时不机械复制原型档：删除未被作者确认进入故事内文化语境的现实作品、角色、活动、原型编号和未绑定信息，只保留角色已采用的轮廓、色彩、分件、材质、动态和制作边界。作者已经明确确认的现实作品及其虚构角色名，可以作为人物消费、COS、衣装审美或流行文化引用保留；这种保留不使正式文件依赖原型档。
- 正式文件不得反向链接或依赖 `.prototypes/clothes/`。

## 状态

| 状态 | 含义 |
|---|---|
| `reference_only` | 只有可采用的视觉结论，尚未完成结构拆解 |
| `analyzed` | 已完成可复核的原貌拆解，仍未形成项目改造方案 |
| `adapting` | 正在比较或设计项目化／定制版本 |
| `candidate_ready` | 候选规格已完整，但尚未写入正式真源 |
| `transferred` | 已将确认结果重新写入正式文件；原型档只保留设计边界与去重价值 |
| `retired` | 停止采用，但保留用于去重、避错或历史回查 |

状态只说明原型档处理进度。`candidate_ready` 不等于人物已经拥有、场次已经采用或正文已经兑现。

## 信息边界

- 官方名称、角色对应与真人复刻判断分别记录，不以配色相似代替来源核验。
- 服装档只保留已收敛的视觉结论、官方命名链接、版本关系和未知项；媒体文件信息和分析过程不入档。
- 临时媒体可放入被 Git 忽略的 `.prototypes/cache/clothes/CLO-xxxx/`，不进入主档、索引或版本库。
- 滤镜、风力、镜像、拍摄角度与平台 UI 造成的效果不写成服装固有事实。

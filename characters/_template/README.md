# 人物模板说明

> 本目录只负责人物静态模板分流，不横向展开具体人物正文或动态状态。模板存在不代表人物已经进入正典。本模板按本项目都市星辰契约世界观维护；不得补入真源未登记的修炼、法器、化形、双魂等体系词汇。

## 选用说明

- 人物档案统一从 `主卡.md`、`形象.md`、`衣装/_GRAMMAR.md` 三类公共模板中按需取用；`主卡.md` 是人物建档基础，`形象.md`、`衣装/_GRAMMAR.md` 与角色专属 `契约.md` 按人物调用需要创建。
- 先选目录层级，再复制当前需要的模板；主次与登场状态由 `major` / `minor` / `preentry` 目录和对应索引承担。
- `major` 适合主角、核心配角、关键对手、长期回归角色。
- `minor` 适合阶段性配角、一次性推动角色、信息承载角色。
- `preentry` 适合尚未正式登场、但已经完成设定的人物。
- 人物目录编号登记在 `major/_index.md`、`minor/_index.md` 或 `preentry/_index.md` 对应分层索引中（如 `M-01`、`F-01`），跨三个分层索引全局唯一，且不随目录层级迁移而改变。主卡中的 `CHR-*` 是机器检索使用的永久人物身份，一经分配不得修改或复用；新人物取全项目下一个未使用编号。

## 文件职责

- `主卡.md` 写“这个人是谁、怎么行动、和谁有关、边界是什么”，只保留星辰契约摘要，不展开能力机制。
- `契约.md` 写角色实际持有的星辰、权柄、具体能力、个人限制、登记状态与异变表现，不重复人物性格、职业和关系正文。
- `形象.md` 写“这个人长什么样、身体与气质如何被正文调用”。
- `衣装/_GRAMMAR.md` 写角色跨场景稳定的审美基因、现代衣柜范围、妆造逻辑与调用边界，不是完整衣柜清单，也不负责某一场具体穿什么。
- `关系/` 是**可选**的静态关系层：`关系/_index.md` 是当前角色视角的唯一关系摘要表（主卡不维护关系表，只留一行指针）。同一关系可以在双方索引中分别登记；两边各自记录本角色视角下的关系性质、结构重量、责任与写作边界，不要求文字一致，也不要求机械补齐另一侧。
- 重要配对按需建立 `关系/<对象>.md`，可含非露骨「亲密 A 场层」。owner-centric 只约束这份完整配对档：全项目只保留一份，放在戏份更重一方的角色目录下，不建立镜像档；双方摘要若都存在，可以共同指向这份配对档。关系档是静态层，不登记剧情节点、剧情阶段、完成判据或未来事件；按章推进仍走 `context/characters/`，正式剧情节点从剧情侧引用人物卡或关系档。露骨内容一律归 `specialties/intimacy/characters/`，正文管线不读该目录。
- 每份重要配对关系档以“说话者 → 对象”维护有向称呼表，统一区分公开／工作、私人／日常及改口边界。人物互称不另建中央矩阵；露骨角色称呼与玩法称呼仍归 `specialties/intimacy/characters/`。
- `关系/_index.md` 的人物对象使用对应主卡正式姓名；确有必要登记组织、匿名责任方或程序接口时，使用正式名称或稳定描述，不为补齐关系表虚构人物卡。艺名、昵称与关系称呼只写在主卡身份字段或配对档称呼表，不混入对象身份。
- 动态状态（当前处境、关系推进、出场记录）写入 `context/characters/人物名.md`，不要塞回静态卡。
- `major` 可以写厚，但复杂能力细则仍应进入 `契约.md`，不以超长段落堆在主卡。
- `minor` 保持轻量，重点保证功能清楚、形象完整、关系可调用。

## 衣装档案创建与填写协议

- 已有正式 `衣装/_GRAMMAR.md` 的人物按公共模板维护，不因人物层级、性别或关系位置使用第二套模板。
- 尚无衣装页的人物不为凑齐三个必备页机械补档。只有人物需要跨场景稳定调用衣装、职业与身份切换需要长期区分，或作者明确要求时才创建；一次性造型留在章节或施工层。
- 衣装页固定的是审美基因与组合逻辑，不是代表色加固定套装。正文可以在不违反色谱、材质、轮廓、职业要求和禁区的前提下调用同类现代款式。
- 色彩写核心色域、邻近色域、低频强调色、场景偏移和禁用方式。除非确有正式事实依据，不用单一“禁用色”封死整个颜色。
- 稳定锚点允许存在，但只作轻点，不要求每次出场复刻。没有稳定锚点时删除对应小节。
- 场景衣柜按人物真实生活选填。没有职业、正式社交、危机行动或舞台需求时，删除相应小节，不为模板完整度发明场景。
- 少量现代单品可以用于解释组合逻辑，但不得穷举库存、品牌、价格，也不得把例子写成人物已经拥有的唯一搭配。
- 衣装页不得维护关系阶段、出场进度、临时伤势或章节状态；动态变化进入 `context/characters/` 或具体章节承载层。
- 主 `衣装/_GRAMMAR.md` 不维护私密偏好或情趣衣装库存。已确认由角色持有、会跨场景复用的具体私密／情趣服装，按需建立 `衣装/<服装名>.md`，并在 `衣装/_index.md` 登记；不因市场分类、视觉参考或一次性场景机械建档。
- 具体衣装档案可以定义这件衣物的核心张力、材质反馈、主导互动和预期衣物结果，但不能代替人物授权：稳定私密偏好、避让与脱换语言进入 `specialties/intimacy/characters/`；本场实际选择、顺序、损坏、替换与事后流向进入专项施工或章级设计。
- “丝袜是撕还是抚摸”必须逐件做设计判断，不能由丝袜、蕾丝、系带或露肤程度自动推出。每件只设一个主导路径，最多一个克制变体；撕裂路径还须说明可撕结构或牺牲层、皮肤保护和替换／丢弃方案，否则默认采用整理、移位、解扣或褪下。
- 亲密参考素材、市场分类和候选款式不构成人物事实；普通衣装页中的职业服装、衣装便利性和既往选择均不自动产生当次亲密授权。

## 契约档案创建条件

- **非契约者**：不创建 `契约.md`，主卡星辰契约摘要写“不适用”。
- **契约状态未确认**：不创建正式 `契约.md`；能力候选与缺口转入分析层待确认记录，主卡不设占位字段。
- **已确认是契约者，但只定权柄方向**：可以创建轻量 `契约.md`，只写已确认方向与边界；其余未确认内容登记于分析层。
- **权柄、具体能力或星辰异变已经确认**：创建完整 `契约.md`，并由主卡摘要链接过去。
- 不为追求模板完整度保留空小节；没有复合能力、异变细则或暴露管理时，删除对应章节。

## 星辰契约真源边界

- `worldbuilding/systems/星辰契约.md`、`星辰权柄.md`、`精神之海.md` 与 `星辰异变.md` 负责公共机制。
- 角色的 `契约.md` 负责公共机制在该角色身上的实际落点，不重新定义权柄共通规则。
- **星辰不设星名**：设定层一律以「契主＋权柄方向」指称；个别星辰若值得有名字，让它在剧情中被命名。
- 星辰性质、成立条件、代价、登记状态与精神之海评级等细则，未拍板前不写入正式人物档案，转入分析层待确认记录承接。
- 拍板日期、更新时间、更新原因与讨论过程不写入正式人物档案，决策过程以 git 历史与分析层记录为准。

## 写作边界

- 新人物进入正典前，必须确认其身份、关系、势力、契约状态和出场位置不与既有文件冲突。
- 新建人物或改名时，必须从 [人物索引](../_index.md) 进入三个分层索引并核对相关人物主卡；正式姓名、艺名、公开身份名与稳定常用名写入人物主卡，正文称呼、对话昵称和视角化叫法核对对应 `关系/<对象>.md` 的有向称呼表。能力名与世界观术语由各自正式真源负责，不在人物目录另建中央占用表。
- 若人物设定涉及星辰契约体系、势力格局、重大关系或线索真相，先取得作者确认，再写入正式人物档案（真源顺位见 `zen/bible.md`）。
- 静态人物档案可以引用世界观、组织与其他静态人物档案；不得依赖剧情施工、专项人物档案、章节或动态上下文。
- 单场衣装、动作、关系兑现与其他执行规格由剧情或专项层引用人物档案，不从静态人物档案反向链接执行文件。
- 女主入场线随各人物卡确认。
